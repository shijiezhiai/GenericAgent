## Tauri 构建产物同步到部署目录 + 架构正解（10:42-10:55）

- **架构正解（之前判断错的更正）**：Tauri `.app` **不是前端载体**——`src-tauri/src/lib.rs` 的 `spawn_bridge_process` 启动 `frontends/desktop_bridge.py` 当子进程，WebView 加载 `http://127.0.0.1:14168/`；真正 `app.js` 由 bridge 从 `frontends/desktop/static/` 提供，**不内嵌进二进制**（二进制只内嵌 `loading.html` 跳板，明文 grep 不到 conv-folders/loadConvFolders，gzip 流也解不出——前端被压缩编码）。所以"Tauri 与浏览器对齐"从来只取决于**服务端**（desktop_bridge.py + static/app.js + /conv-folders 数据），与是否重打二进制无关。之前说"旧二进制内嵌旧前端导致不对齐"是错的。
- **重打构建环境坑（macOS）**：默认 `cc`=/opt/homebrew/bin/cc（非 Apple，链接不认 `-Wl,-exported_symbols_list`）；`/usr/bin/clang` 缺 SDK sysroot（编译 `mac-notification-sys` 报 `Cocoa/Cocoa.h not found`）。正解：`CC/CXX/链接器` 全指向 `/Library/Developer/CommandLineTools/usr/bin/clang` + `SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk` + `DEVELOPER_DIR=/Library/Developer/CommandLineTools` + `CARGO_TARGET_AARCH64_APPLE_DARWIN_LINKER=同 clang`。`npm run tauri build` 后台跑，cargo 全量重编约 1m30s。

## 自包含 bundle app 真机验收通过（19:4x）——"完全无外部依赖"达成
