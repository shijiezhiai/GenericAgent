## 调试发现：右键改了没生效 → webview 持旧 JS（非代码 bug）
用户报"会话项右键仍弹原生文字菜单"。排查结论：**代码正确、同步正确，是运行态 webview 内存里还是旧 app.js**。
- jsdom 最小复现证明派发逻辑对 conv-item 命中 conv-menu 分支 + preventDefault；真实 DOM 中 .conv-list 在 ASIDE.rightpanel、不在 .msg-area，不会误入选区分支。
- 网关 bundle 模式 `ensure_writable_runtime()` 返回 `~/Library/Application Support/GenericAgent/app`，static_dir=`.../app/frontends/desktop/static`（= target A），每次请求从磁盘读（无 Cache-Control），所以磁盘新代码 reload 即生效。
- 但 Rust 注入 `keydown` 禁用 F5/Ctrl+R，且 app 无 webview 重载快捷键 → 普通操作不重读静态文件 → **必须 quit & reopen** 才能加载新 JS。旧 app.js 无 conv-item 全局右键处理 → 原生菜单，正是用户所见现象。
- 教训：前端热改后若"没生效"，先怀疑运行态 webview 没重载，而非代码。重启 app 即验证（单实例，kernel/bridge 受监管会重连）。不要盲目改代码。
- 这两个改进当天已落地（见下"Rust 改动"段）。

## Rust 改动：网关 no-cache + Cmd+R 重载（已做）
- `frontends/desktop_gateway/src/lib.rs`：`index_handler` 与 `static_file_handler` 响应头加 `Cache-Control: no-cache`（每次请求问服务器，配合磁盘实时读 → 热改即时生效）。
- `frontends/desktop/src-tauri/src/lib.rs`：注入 JS 改写——把 `(metaKey&&key==='r')||(ctrlKey&&key==='r')||F5` 从「禁用列表」改为 `e.preventDefault(); location.reload()`；保留 F12/Ctrl+Shift+I 禁用、contextmenu 仅 preventDefault（前端右键菜单照常）。
- 编译（增量 1m45s，特制 env + dangerouslyDisableSandbox）：`cd frontends/desktop/src-tauri && cargo build --release --offline`（gateway 是 path 依赖嵌入主二进制，一并重编）。
- 替换+签名：`pkill` 旧 app → 备份旧二进制到 /tmp → `cp target/release/ga-desktop /Applications/GenericAgent.app/Contents/MacOS/` → 清掉 Contents/MacOS 内残留 `ga-desktop.bak-20260801-150056`（移到 /tmp）→ `xattr -cr` + `codesign --force --deep --sign -` → 验证 `valid on disk`。
- 实测：`open` 启动后网关 10s 就绪，`curl --noproxy '*' /app.js` 响应头含 `cache-control: no-cache` ✅；新二进制含 `location.reload` ✅。Cmd+R 真实按键需用户手测（自动化测不了 webview 键盘事件）。
- 附带效果：编译后 app 是全新启动，webview 已加载最新前端 → 之前"会话项右键弹文字菜单"的现象现应消失（旧 webview 持旧 JS 才是根因）。

## Cmd+R 没反应 → 改为前端 listener（修正）
- 现象：上轮在 Rust eval 注入的 keydown 里加 `Cmd+R→location.reload`，用户实测没反应。
- 根因：`src-tauri/src/lib.rs` 注入的 `w.eval()` 在 `w.navigate(14168)` **之后立即**调用，而 navigate 是异步的 → eval 可能挂在导航前的旧 document，新页面(14168)没有该 listener。之前 contextmenu "看似生效"是旧 JS 自带 preventDefault，不能证明新 eval 挂对页面。
- 修复：把 `Cmd+R` 的 keydown 监听**从 Rust eval 移到前端 `app.js`**（页面 context 内，listener 必挂对 document），`if((e.metaKey||e.ctrlKey)&&(e.key==='r'||e.key==='R')){e.preventDefault();location.reload();}`。Rust eval 的 Cmd+R 分支保留未删（大概率因时机未生效；即便生效也只是可能双 reload，无害）。
- 已同步三处 + 重启 app，`curl` 确认运行态 app.js 含 `location.reload`。Cmd+R 真实按键需用户手测（WKWebView 一般不放行 Cmd+R 键盘事件，前端方案应可靠）。若仍无效 → 上 `tauri-plugin-global-shortcut`（AppKit 原生层注册，绕过 webview 键盘事件）。

## 文件项右键"叠加三效果"修复
- 现象：右键 `.files-item` 同时出现①单击效果（选中高亮变化）②右键菜单③选中文字。期望只弹菜单。
- 根因：①来自上一轮 contextmenu 分支里 `_filesSelected.clear(); add(fpath); updateFileSelectionUI()`（右键强行改选中态，看着像单击）；③来自右键 `mousedown`(button=2) 阶段浏览器已开始文本选区，`e.preventDefault()` 在 contextmenu 阶段太晚拦不住。
- 关键确认：`toggleFilesMenu` 的菜单项操作直接基于 `btn.dataset.path`（`handleFileAction(act, path, b)`），**不依赖** `_filesSelected`，所以右键根本无需改选中态。
- 修复：① 删掉 contextmenu 分支的选中态改变逻辑，改用 `e.preventDefault()+e.stopPropagation()` 并 `window.getSelection().removeAllRanges()` 清选区；② 在文件项渲染循环（`el.querySelectorAll('.files-item')`）里加 `item.addEventListener('mousedown', e=>{if(e.button===2)e.preventDefault()})`，从 mousedown 阶段阻止右键文字选区。
- 已 `node --check` + 同步三处并 md5 一致。Cmd+R 重载即生效。

## 文件项右键菜单定位修正（光标位置）
- 现象：右键文件项菜单弹出在「项最右侧」（⋯ 按钮旁），期望弹出在光标所在位置。
- 根因：`toggleFilesMenu(btn)` 把下拉 `.files-menu-dropdown` `appendChild` 到 `btn.parentElement`（`.files-item-actions`），CSS `position:absolute;right:0;top:100%` → 相对定位在项的 ⋯ 按钮处。其它右键菜单用 `openCtxMenu(menu,x,y)` 走 `position:fixed` 按 `e.clientX/clientY` 定位，唯独文件项没走这机制。
- 修复：给 `toggleFilesMenu` 加可选坐标参数 `(btn, x, y)`。右键场景（`x,y` 传入）时下拉设 `position:fixed;right:auto;top:auto`，先挂到 `document.body` 再测 `offsetWidth/Height` 做边界裁剪后定位到光标，并补 `setTimeout(0)` 后 document `mousedown`(capture) 关闭监听（点菜单外关闭，与 openCtxMenu 同模式）。按钮点击场景（`x,y` 不传）保持原相对定位行为，零回归。
- 右键分支调用改为 `toggleFilesMenu(fbtn, e.clientX, e.clientY)`。已 `node --check` + 同步三处并 md5 一致。Cmd+R 重载即生效。
