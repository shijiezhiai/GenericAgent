### 背景故障链
kernel stdin EOF / 硬崩 → bridge 被连坐或成孤儿 → 网关无 watchdog → `/api/*` 永久 502 → Skill Hub 永远「加载中」。

### A 前端止血（frontends/desktop/static/app.js + styles.css）
- 新增 `SH_API_TIMEOUT=12000` / `shKernelError()` / `shApi()`（AbortController 超时 + 502/503/504 + TypeError → 标记 `kernelDown`）/ `shRenderError()`（渲染卡片，带「重试」+「重启内核」按钮，后者 POST `/kernel/restart`）。
- skills / experts / plugins / mcp 四个 loader 全部接入，不再无限 loading。

### B 网关 watchdog（frontends/desktop_gateway/src/{kernel.rs,lib.rs}）
- `KernelClient` 增 `exit: broadcast::Sender<()>` + `shutdown()`（start_kill+wait）+ `exited()`；reader 循环结束时 drain pending（返回 -32001 "kernel process exited"）再发 exit —— 否则 in-flight 调用会永远挂着（serve() 启动期的 `call("status")` 就是这样卡死的）。
- 新增 `KernelSupervisor`：current(RwLock) / generation(AtomicU64) / fails / restart_lock；退避 `1<<n.min(5)` 秒、MAX_ATTEMPTS=8、`HEALTHY_UPTIME=60s` 后重置计数。**代际检查**防手动重启与 watchdog 抢跑。
- `on_exit`/`restart` 里先 `current.write().take()` 拿走再 `shutdown()`，**不持写锁跨 await**，让并发 `call` 快速失败而不是排队。
- lib.rs：`AppState.kernel` 改 `Arc<KernelSupervisor>`；新增 `GET /kernel/state`（`{up,generation}`）、`POST /kernel/restart`；`is_kernel_down()` 把内核类错误从 500 降级成 **503**（前端据此判断 kernelDown）。

### 血泪教训 #1：部署到了不存在的目录，白查两小时

### 教训 #8：模块级注入的时序陷阱
`import conductor_core` 时模块级 `task_history = TaskHistoryStore()` 立即执行 _load()，
而 `attach_store()` 在其后才调用 → 记录按文件加载、永不迁移。
**修复**：attach_store() 内重新 `task_history._load()`（此时 store 已注入 → 走 DB 迁移）。
通用规则：模块级有状态的注入，注入函数必须触发一次"重载"，不能假设调用方顺序。
