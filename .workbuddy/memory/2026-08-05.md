## 项目资产：支持引用本地目录（原型）

### 结论先行
- GA「项目」内部两类桶：**资产(assets)**= 项目活代码/工作目录（含 `workspace` 只读特殊资产）；**资料库(library)**= 只读参考材料（网页/PRD/文档）。多个代码 repo 应放**资产**，不是资料库。
- 原缺口：一个项目只能引用**一个**外部本地目录（`workspace`，走全局 registry、资产视图里只读）。增补「多本地目录引用」作为可编辑资产。

## 修复：拖动窗口能力丢失（双击最大化改造后用户反馈"拖动窗口的能力没有了"）

### 根因
- 此 webview 经网桥(http://127.0.0.1:14168)加载，Tauri **不注入** `window.__TAURI_INTERNALS__`。
- 原生 `data-tauri-drag-region` 属性在 mousedown 时会调用 `window.__TAURI_INTERNALS__.invoke('plugin:window|start_dragging')`（见 tauri-2.11.1/src/window/scripts/drag.js），因 internals 不存在 → 原生拖拽在此 webview 完全失效。所以顶带区域的实际鼠标事件全被 webview 接收，macOS 原生 Overlay 标题栏拖拽也接不住（8899 日志曾实证 y=12-13 事件进 webview）。
- 结论：拖动必须走网关，与双击最大化同一模式。

### 改动
1. `frontends/desktop/src-tauri/src/lib.rs` WIN_CTRL 闭包
   - 新增 `"start_drag"` 分支：`handle.run_on_main_thread(move || { w.start_dragging() })`。必须 main thread（AppKit 限制）；按键在 mousedown+move 期间仍按住，调用即进入系统拖动。
   - `start_dragging` 经 `dispatcher` 调 WRY/macOS，Rust 内部调用绕过 capability 权限系统（无需改 capabilities）。
   - 网关 `POST /__win/{action}`（any 路由）已把 action 透传给 WIN_CTRL → 无需改网关路由。
2. `frontends/desktop/static/index.html` 顶部 IIFE
   - 原"双击即最大化"改为"拖拽+双击"合并判定：mousedown 在顶带(TOP_ZONE=56,非交互)记录起点；mousemove 位移>4px → `fetch('/__win/start_drag')` 发起拖动；mouseup 无位移且距上次点击<350ms → `fetch('/__win/toggle_maximize')` 最大化/还原。
   - 拖拽与双击用移动阈值分离，互不误触；顶带空白处 `e.preventDefault()` 防文本选中。交互控件(run-state/按钮/logo)仍被排除。

### 部署与验证
- 重编 ga-desktop：`env PATH=.../CommandLineTools/usr/bin:... SDKROOT=.../MacOSX.sdk LIBRARY_PATH=/usr/lib cargo build --release --offline`（src-tauri 下）。首编 E0505（app 既借又 move）→ 改用 `let app2 = handle.clone(); handle.run_on_main_thread(move || { app2... })` 修复，二编通过。
- 部署二进制：`cp target/release/ga-desktop → /Applications/GenericAgent.app/Contents/MacOS/ga-desktop`；`xattr -cr`；`codesign --force --deep --sign -`；`codesign -v` OK。
- 三处 index.html 同步（源码仓/app-support/bundle），md5 一致 `865e5d31…`。
- 重启 GA。验证：`POST /__win/start_drag`=200、`POST /__win/toggle_maximize`=200、网关根含 `start_drag`(2)/`toggle_maximize`(1)/无 `8899`。

### 备注（待用户实测）
- 路由/闭包已实证可达；真实拖动需在按住左键+移动时由 `start_dragging` 接管。若实测拖动仍无效，最可能原因：macOS `start_dragging` 要求严格在 mouse 事件内调用，而 `run_on_main_thread` 有微小延迟。备选方案：前端在 mousedown 即发 start_drag（不等 move 阈值），或在 drag.js 注入路径上做文章（但 internals 缺失，原生拖拽不可用）。
