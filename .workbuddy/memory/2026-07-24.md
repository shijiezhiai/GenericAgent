## Bug 修复：项目页资料库条目三点菜单点击不弹菜单（已解决）

- **现象**：资料库 `.ph-lib-more` 竖三点按钮点击不弹菜单，菜单"完全不出现、无报错"；hover 时按钮正常出现。
- **真实根因（纠正，原 pointer-events 假设错误）**：所有 `position:fixed` 浮层（`#conv-menu`/`#ph-task-menu`/`#lib-menu`/`#folder-menu`/`#move-menu` 及 `#lib-preview-modal`）原本嵌在 `<aside id="rightpanel">` 内。资料库在项目主页视图渲染时，右侧会话面板 `#rightpanel` 是折叠收起的（`display:none`）。浏览器规则：**`display:none` 祖先的后代即便 `position:fixed` 也不渲染** → 菜单 `offsetWidth/Height=0`、`getBoundingClientRect=0×0` → 屏幕完全看不到，且无任何报错。用 Playwright 直连真实 14168 + 探针 `getComputedStyle`/`getBoundingClientRect` 沿祖先链 walk，定位到 `#rightpanel{display:none}` 为隐藏源头。
  - 关键误区：之前误判为图标 SVG 缺 `pointer-events:none` 导致 `closest` 失败；但 Chrome 里 `closest` 从 `<path>` 上行能命中 `<button>`，所以那不是浏览器失败的原因。给图标加 `pointer-events:none` 仍保留作跨引擎健壮性改进（与已有 `.conv-session-toggle svg` 一致），但它不是本次修复点。
- **修复**：`frontends/desktop/static/index.html` 把上述 5 个浮层菜单 + `lib-preview-modal` 从 `#rightpanel` 内搬出，放入 `#rightpanel` 闭合之后、顶层可见容器内的 `<div id="ctx-layer">`（其祖先 `#app`/`.body.rp-collapsed` 均 `display:flex/grid`，非 none；无 transform/filter 创建包含块，故 `position:fixed` 定位参考不变）。按 ID 引用，JS 无需改动。
- **验证（Playwright 直连真实 14168）**：点三点→`#lib-menu` `rect` 由 `0×0` 变为 `{125×142, x:785,y:248}` 可见；点"预览"→`#lib-preview-modal` 出现（该弹窗同样被此 bug 藏住，一并修好）；点别处→菜单关闭；无 pageerror。`library-add-modal`/`library-ref-modal` 本就在 `<body>` 直接子级，不受影响。
- **注意**：bridge 用 aiohttp 实时读盘提供静态文件，改完刷新即生效（无需重启服务）。Tauri 桌面端同理（静态文件实时读盘），该修复对其也生效。
- 复现/探针脚本在 `/tmp/librepro/`（diag2.js / probe2.js / probe3.js / verify.js 等），不入库。

## Bug 修复：项目页「资产」tab 点击预览，二进制文件被包成 JSON 无法显示（已解决）

- **现象**：项目主页 → 资产 tab → 点某文件「预览」👁，二进制文件（图片/PDF 等）在弹出的新标签里显示成一段 JSON 文本，无法正确渲染。
- **根因**：前端 `_assetPreview()`（`frontends/desktop/static/app.js`）用 `window.open('/api/files/read?path=...')` 打开预览；而后端 `files_read_handler`（`frontends/desktop_bridge.py`）始终返回 JSON `{ok, content, name, size}`（文本读取 + JSON 包装）。任何文件经此端点都会被当 JSON 展示，二进制尤其明显。
- **修复**：
  1. 新增 `files_raw_handler`（`desktop_bridge.py`，仿 `project_library_raw_handler`）：沿用与 `files_read` 相同的目录白名单（upload/sche/chat/ga_root 内），按扩展名推断 content-type，以 `Content-Disposition: inline` 流式返回原始字节（25MB 上限）。
  2. 注册路由 `GET /api/files/raw` → `files_raw_handler`。
  3. `_assetPreview()` 改为打开 `/api/files/raw?path=...`：图片/PDF 由浏览器内联渲染，文本显示为纯文本（不再是 JSON 包装），未知二进制走下载。
- **验证**：`ast.parse` 通过；白名单逻辑与既有 `files_read` 一致，项目目录文件（`in_ga`）与上传文件（`in_upload`）均覆盖。静态文件 aiohttp 实时读盘，刷新即生效（无需重启服务）。

## 修复：面包屑「项目」竖向显示 + 项目名未显示全

- **现象**：进入项目后，面包屑「项目」两字竖向堆叠、很丑；项目名（尤其长中文名）显示不全。
- **根因**：`.ph-crumb-current`（项目名）`white-space:nowrap` 但没有 `min-width:0`，其 min-content = 整段文本宽度，在 flex 行里霸占空间、无法收缩，导致同行的「项目」按钮被挤压到近 0 宽 → 两个 CJK 字换行成竖向；同时项目名本身因无法收缩而溢出而非省略号截断。
- **修复（仅 styles.css）**：
  - `.ph-crumb-link`（「项目」按钮）加 `flex:0 0 auto; white-space:nowrap;` → 不再被挤压、不换行。
  - `.ph-crumb-current`（项目名）改为 `flex:1 1 auto; min-width:0;` + 保留 `overflow:hidden;text-overflow:ellipsis;white-space:nowrap;` → 超长时正确省略号截断。
  - `.ph-breadcrumb` 加 `flex:1 1 auto; overflow:hidden; min-width:0;`，`.ph-breadcrumb-bar` 加 `min-width:0; gap:12px`，`.ph-crumb-icon`/`.ph-crumb-sep` 加 `flex:0 0 auto;` → 面包屑整体在窄栏内正确收缩，右侧邀请按钮不被挤占。

## 修复：具体项目页「只显示一个大大的文件夹图标」整页乱掉

- **现象（用户二次反馈）**：点进具体项目后整页乱掉，只看见一个巨大的文件夹图标。
- **真因**：图标由 `phosphor-icons.js` 的 `gaHydrateIcons()` 把 `<span class="ph-crumb-icon" data-ga-icon="folder">` **整体替换**为 `<svg class="ph-crumb-icon">`（phosphor SVG 只有 viewBox、无 width/height）。我之前写的尺寸规则 `.ph-crumb-icon svg{width:14px}` 是**后代选择器**，对“本身就是 svg 的 .ph-crumb-icon”无效 → svg 无尺寸 → 撑到 ~300×150+，面包屑条被顶到 384px 高，下方内容区塌成 0，整页只剩大图标。
- **验证手段**：用 Playwright + 本机 Google Chrome 无头渲染 `frontends/desktop/static/index.html`，手动激活 `.page--project-home` 并设长项目名，量取几何。修复前 breadcrumbBar=384px、folderIcon=355×355、content height=0；修复后 breadcrumbBar=77px、folderIcon=14×14、content height=152，且「项目」横排、长名省略号截断。
- **修复（仅 styles.css 一行）**：`.ph-crumb-icon{ ... width:14px; height:14px; color:var(--text-2,#999); }` —— 把尺寸/颜色直接写在元素自身 class 上（替换后 svg 仍带此 class），同时保留 `.ph-crumb-icon i,.ph-crumb-icon svg{...}` 兜底。
- **泛化规则**：本仓库图标尺寸规则必须同时命中替换前的 `span[data-ga-icon]` 与替换后的 `svg`，即写在元素自身 class 上；只写 `.X svg` 对“本身就是 svg”的图标无效。已写入项目 MEMORY.md「Desktop 前端图标尺寸约定」。
- **验证**：静态文件刷新即生效；HTML/JS 未改（「项目」仍是 `<button id="ph-crumb-project">`，原生支持 Enter/Space 与焦点）。

- **修复（环境无关，彻底）**：放弃 `window.open`，改为**应用内弹窗**渲染（同源相对路径，与资料库预览一致）：

- **服务器重启**：新增 Python 路由必须重启 bridge 才生效（静态文件才「刷新即生效」）。已杀旧进程（79546）、用同解释器（/opt/homebrew/Cellar/python@3.11/3.11.13/.../Python）+ `BRIDGE_HOST=0.0.0.0` + 同 cwd 重启（现 PID 97408，后台任务 ByuxSO）。重启后 curl `/api/files/raw` → `HTTP 200 image/png 38573`，正确返回图片字节。

## 三次修复：资产列表里 .sh / .jq 等未知扩展名文件显示成文件夹图标且无法预览

- **现象**：资产 tab 列表里 `.sh`、`.jq` 等文件显示成 📁 文件夹图标，点预览无反应（被挡掉）。
- **两个关联根因**：
  1. `fileIcon(type)`（`frontends/desktop/static/app.js`，约 14618 行）对**不在映射表里的扩展名一律 fallback 成 `'📁'`**（文件夹图标）。`.sh`/`.jq` 未注册 → 误显文件夹图标。
  2. 预览函数 `openAssetPreview()` 用 `row.querySelector('.pa-icon').textContent === '📁'` 判断「是不是目录」来跳过预览；`.sh`/`.jq` 因被误标成 📁 → 被当成目录 `return` 掉，无法预览。
- **修复（仅 frontends/desktop/static/app.js）**：
  1. `fileIcon` 的 fallback 由 `'📁'` 改为通用文档图标 `'📄'`；并给常见代码/配置类型补表：`sh/bash/zsh:'🐚'`、`jq:'📜'`、`cfg/conf/ini:'⚙️'`、`env:'🔧'`。目录图标 📁 仅由 `renderPhAssets` 对 `type==='dir'` 显式设置，与 fallback 解耦。
  2. `renderPhAssets` 渲染行 `<tr>` 时新增 `data-type="<type>"`（dir/file/workspace 原样）。
  3. `openAssetPreview` 把「目录不预览」的判定由 `.pa-icon` 字形改为 `row.dataset.type === 'dir'`，不再误伤普通文件。
- **验证**：`node --check app.js` 通过；静态文件 aiohttp 实时读盘，刷新即生效（无需重启 bridge）。已 curl 线上 `/app.js` 确认含 `sh:'🐚'`、`data-type=`、`row.dataset.type || '') === 'dir'`。
