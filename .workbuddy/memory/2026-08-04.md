## 追加修复（定时任务页空态提示 bug——上条隐患的第 2 例，改全局根治）
- **症状**：任务页已有定时任务，仍显示「选择下方对话，开启你的第一个任务吧」（page.tasks.emptyTitle）。
- **根因**：`.task-empty{display:flex}` 优先级压过 UA 对 `[hidden]` 的 `display:none`，JS 里 `taskEmptyEl.hidden=true` 不生效。与 7/29 修的 `.wsm-empty` 完全同款（上次只做了局部补丁 `.wsm-empty[hidden]{display:none}`，治标不治本）。
- **根治**：styles.css 第 6 行加全局规则 `[hidden]{ display:none !important; }`，任何显式 display 类规则都不得覆盖 hidden 属性。已同步源码仓 + app-support + bundle + dev 构建源四处，md5 一致；网关 `curl --noproxy '*' http://127.0.0.1:14168/styles.css` 实测已含新规则（仅静态改动，浏览器重载即生效，无需重启内核）。
- **教训沉淀**：不要再为单个元素打 `[hidden]` 补丁；凡 display 类规则与 hidden 混用的问题统一靠全局 `[hidden]{display:none !important}` 兜底。

## 修复"进行中的会话突然结束、已输出内容丢失"（partial 崩溃 salvag 机制）
- **现象**：会话里只剩用户消息的灰色气泡，assistant 答复凭空消失，无任何报错。
- **根因**：assistant 完整消息只在 turn 正常结束时才 `add_message` 落库；流式期间内容仅存进程内 `sess.partial`。内核进程一旦死亡（崩溃或 `/kernel/restart`，bridge 已并入内核进程），sessions/partial 全丢；新内核从 DB 重载会话=只有 user 消息+idle，前端 poll 非 busy 时静默 `draftEl.remove()`，观感即"回答被吞"。
- **修复**（db_store.py + desktop_bridge.py + static/app.js）：
  1. DB 新表 `partial_state`（session_id PK, content, curr_turn, turn_segs, updated_at）；`ensure_schema` 幂等建表，无需 bump SCHEMA_VERSION。
  2. bridge `_snapshot_partial`：submit_prompt force 初始写；心跳/next 更新 2s 节流写；done/cancel/error/delete 四路 `_clear_partial_snapshot`。
  3. 新内核 `__init__` 里 `_load_sessions` **之前** `_salvage_interrupted_turns()`（顺序关键：salvage 直接 DB 写消息并 bump msg_seq，先加载会留 stale seq 撞主键）；残留 partial 转 assistant 消息（stopped=True, interrupted=True, turn_segs 保留），空内容/会话已删则仅清理。
  4. 前端 normalize 透传 `interrupted`；assistant 渲染对 interrupted 显示 `msg.interrupted` 提示（中英 i18n 已加），区别于手动 stopped。
- **端到端验证**：临时会话流式中 `pkill -9` 内核 → generation+1 重启后 poll 到 salvaged 消息（stopped+interrupted，内容与 kill 时快照一致）；正常完成路径快照被清理不误 salvage。
- **排查手法沉淀**：`/kernel/state` generation 变化 + `temp/kernel_store.port` mtime 可定位内核重启时刻；`/session/{sid}/messages` 直接看落库消息判断"丢了"还是"没存"。DB 独占锁外部不能直读，验证走 HTTP API。
