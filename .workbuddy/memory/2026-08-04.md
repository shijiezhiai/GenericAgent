## 修复"进行中的会话突然结束、已输出内容丢失"（partial 崩溃 salvag 机制）
- **现象**：会话里只剩用户消息的灰色气泡，assistant 答复凭空消失，无任何报错。
- **根因**：assistant 完整消息只在 turn 正常结束时才 `add_message` 落库；流式期间内容仅存进程内 `sess.partial`。内核进程一旦死亡（崩溃或 `/kernel/restart`，bridge 已并入内核进程），sessions/partial 全丢；新内核从 DB 重载会话=只有 user 消息+idle，前端 poll 非 busy 时静默 `draftEl.remove()`，观感即"回答被吞"。
- **修复**（db_store.py + desktop_bridge.py + static/app.js）：
  1. DB 新表 `partial_state`（session_id PK, content, curr_turn, turn_segs, updated_at）；`ensure_schema` 幂等建表，无需 bump SCHEMA_VERSION。
  2. bridge `_snapshot_partial`：submit_prompt force 初始写；心跳/next 更新 2s 节流写；done/cancel/error/delete 四路 `_clear_partial_snapshot`。
  3. 新内核 `__init__` 里 `_load_sessions` **之前** `_salvage_interrupted_turns()`（顺序关键：salvage 直接 DB 写消息并 bump msg_seq，先加载会留 stale seq 撞主键）；残留 partial 转 assistant 消息（stopped=True, interrupted=True, turn_segs 保留），空内容/会话已删则仅清理。
  4. 前端 normalize 透传 `interrupted`；assistant 渲染对 interrupted 显示 `msg.interrupted` 提示（中英 i18n 已加），区别于手动 stopped。
- **端到端验证**：临时会话流式中 `pkill -9` 内核 → generation+1 重启后 poll 到 salvaged 消息（stopped+interrupted，内容与 kill 时快照一致）；正常完成路径快照被清理不误 salvage。
- **排查手法沉淀**：`/kernel/state` generation 变化 + `temp/kernel_store.port` mtime 可定位内核重启时刻；`/session/{sid}/messages` 直接看落库消息判断"丢了"还是"没存"。DB 独占锁外部不能直读，验证走 HTTP API。

## 修复"复制/新建模型保存报 method not allowed"（网关路由既有缺陷，非复制功能 bug）
- **根因**：Rust 网关 `desktop_gateway/src/lib.rs` 对 `/model-profiles` 只注册了 `get(model_profiles_list)`；axum 对"路径命中已注册路由但方法未注册"直接回 **405**（allow: GET,HEAD），不走 fallback 代理。实测 `POST :14168/model-profiles` → 405，而 `GET/PUT/DELETE /model-profiles/{id}`（带 id）未命中显式路由、落 fallback 代理到内核 bridge 正常。
- **波及面**：所有新建模型操作——普通添加、预设快速接入、复制保存——的 POST 全被 405 挡住；编辑/删除一直正常。该缺陷在 commit 7b5bbe0（legacy bridge 退役迁内核）引入，只迁了 list 漏了 add。
- **修复**：网关补 `model_profiles_add` handler 注册 `.post()`，转发内核早已实现的 `model_profiles.add` RPC（kernel_server.py DISPATCH 里 add/get/update/delete 俱全）。改动半径最小：不动带 id 路由。
- **部署验证**：`cd frontends/desktop/src-tauri` 标准 env 编译 1m 通过；替换 `/Applications/.../Contents/MacOS/ga-desktop`（旧版备份 `/tmp/ga-desktop.bak-0804-method405`，勿留 bak 在 MacOS 目录内）+ xattr -cr + codesign --force --deep，`codesign -v` 通过；pkill+open 重启后实测：POST /model-profiles 空 payload → 业务错误（非 405），完整 payload 新建成功（profileId=8），DELETE 清理后复测 not found，端到端通过。
- **教训**：axum 显式 `.route()` 一旦命中路径就不会再走 fallback；迁移路由时要把该路径的**全部方法**一次性迁齐，迁移 checklist 加一项"列出旧 handler 支持的所有 method 逐一核对"。排查 405 先看 `allow` 头是谁发的（网关 axum vs bridge json_ok），再对照 `.route()` 注册表。

## 真正的根因 + 最终修复(重要,推翻前几轮)
- **前 4 轮都错在假设 Tauri JS API 可用**。加了临时诊断 `overlay_debug` 写 `/tmp/ga_overlay_debug.json`(仅在 invoke 可用时调用),重启后该文件**始终未生成** → 证明 `window.__TAURI__` / `window.__TAURI_INTERNALS__` 在本 webview 里**根本不存在**。
- **根因**:GA 桌面端主窗经网桥 `http://127.0.0.1:14168/`(Rust axum gateway)加载,Tauri **不会向这种 HTTP 源 webview 注入 JS API**。所以:
  - 任何 `invoke('...')`(含 `plugin:window|*`、自定义 `start_drag`/`toggle_maximize`)都静默失败;
  - 之前靠 `whenTauri()` 检测 `window.__TAURI__` 才加 `.tauri-desktop` 类 → 类从未加上 → 全部 Overlay CSS 没生效 → 交通灯与品牌重叠("乱掉"),双击也失效。
- **第 5 轮(本轮)关键动作**: 用 `Read` 直接读取运行截图,终于看清**Overlay 根本没生效**——窗口仍带原生标题栏;进一步排查发现配置是对的,但之前类标记失败导致 CSS 没应用、用户看到的是乱掉的非 Overlay 布局。本轮同时解决:
  1. **布局对齐**:`tauri.conf.json` `trafficLightPosition` 从 `{"x":16,"y":16}` 改为 `{"x":16,"y":8}`,使交通灯在 28px 高中垂直居中;`styles.css` `.tauri-desktop .brand` padding-left 从 110px 回收到 **92px**,既避让交通灯又减少空白。
  2. **双击最大化**:放弃所有 `invoke`/`-webkit-app-region` 方案,新增 **gateway → Rust 窗口控制通道**:
     - `frontends/desktop_gateway/src/lib.rs`: 增加全局 `WIN_CTRL` 闭包 + `set_window_control()` + `POST /__win/:action` 路由。
     - `frontends/desktop/src-tauri/src/lib.rs`: 在 `.setup()` 里注册闭包,根据 action 调用 `WebviewWindow` 的 `maximize`/`unmaximize`/`toggle_maximize` 等。
     - `frontends/desktop/static/index.html`: JS 在 `.brand`/`.page-top` 上捕获双击,通过 `fetch('/__win/toggle_maximize')` 让 Rust 切换窗口最大化/还原。
  3. **拖拽**:移除 `-webkit-app-region:drag`(它吞 JS 双击事件),改由 macOS 原生 Overlay 标题栏处理拖拽。
- **部署验证**:`cargo build --release --offline` 32s 通过;三处 `index.html`/`styles.css` md5 一致;二进制替换、codesign OK;重启后 `curl :14168/__win/maximize` 返回 200,`curl :14168/index.html` 含 `v=255` 与 `/__win/toggle_maximize` fetch 代码,`/kernel/state` 正常。截图确认交通灯与 logo 垂直对齐、间距紧凑。
  - app.js 的 Tauri 调用(`pick_folder`/`notify`)大概率同样失效,但 GA 主功能走 HTTP 到 gateway,故不明显。
- **最终修复(纯 CSS 原生方案,零 JS API 依赖)**:
  1. `index.html`:类标记改为按 **`location.hostname`(127.0.0.1/localhost)** 判断加 `.tauri-desktop`,不再碰 Tauri 全局对象。删除全部 invoke/拖拽/双击 JS(含诊断)。
  2. `styles.css`:`.tauri-desktop .brand`、`.tauri-desktop .page-top` 加 **`-webkit-app-region:drag`**(macOS 原生标题栏行为:单击拖拽 + 双击最大化,系统级,无需 JS);交互子元素 `.brand .brand-logo`、`.brand button`、`.page-top button/.run-state/a/input/select/textarea` 加 `no-drag` 保持可点。`.brand` 左内边距 110px + 隐藏 brand 文字不变。
  3. `lib.rs`:清理掉本轮加的死代码(`start_drag`/`toggle_maximize`/`overlay_debug` 命令及 setup 里冗余的 `w.eval` 类注入)。
- **部署**:`cargo build` 19s 通过;三处 md5 一致;二进制替换+codesign OK;重启 PID 24896;`curl` 验证 `v=253`、`webkit-app-region:drag`×3、无 invoke 残留、`/kernel/state` 正常。
- **结论/经验**:GA 桌面 webview 控制窗口(拖拽/最大化/最小化)只能用 **CSS `webkit-app-region` 原生** 或 **Rust 侧 `w.eval`/命令**;**绝不可依赖前端 `window.__TAURI__` invoke**——它在该 HTTP 源 webview 不存在。以后涉及窗口外观/行为,默认走 CSS 原生或 Rust。

## 修复：复制新建的模型重启/重建后丢失
- **现象**：配置页「复制并修改」新建的模型，运行期可见，但 App 重启（尤指重建/部署后）即消失。
- **排查**：`desktop_bridge.add_model_profile` → `_save_mykey_text` 只写 **运行态** `~/Library/Application Support/GenericAgent/app/mykey.py`，并即时 reload，运行期与**真实内核重启**（`POST /kernel/restart`）均验证可保留（`native_oai_config6` 重启后仍在）。克隆逻辑 `tar --exclude=mykey.py` 也确实保护 app-support/mykey.py。→ 保存层本身没问题。
- **真因**：仓库根 `mykey.py` 是**陈旧副本**（只到 `native_oai_config4`，缺运行期新增的 `config5`/`config6`）。模型增删改从不回写仓库；一旦 rebuild/deploy 以仓库 `mykey.py` 为源覆盖运行态，运行期新增模型即被冲掉。
- **修复**：`desktop_bridge._save_mykey_text` 末尾调新增 `_sync_mykey_to_source(text)`——bundle 运行态（`ga_root` 以 `/app` 结尾）下，把最新 mykey.py 回写「部署源」同名文件。源根定位：①`app-support/.ga_source_root` 标记（已写入 `/Users/mayangyang/code/ai/GenericAgent`）②环境变量 `GA_SOURCE_ROOT`；dev 模式直接 return（ga_root 即仓库根，无需回写）；写失败静默忽略（签名 bundle 等）。
- **一次性对账**：把运行态 `mykey.py`（含 `config5` 等已存在运行期模型）cp 回仓库，使后续重建天然携带；并删掉验证用的测试模型 `config6`，确认运行态与仓库两侧同步移除。
- **部署**：源码仓→app-support→bundle 三处同步 `desktop_bridge.py`、清 pyc、`/kernel/restart`（gen→3）生效；删除模型响应 ok、两侧 grep 校验一致。
- **结论/经验**：凡是写入「用户数据」(`mykey.py` 等 USER_DATA_ENTRIES) 的运行时变更，若重建/部署以仓库为源，必须**同步回仓库**（或部署时 `--exclude` 这些条目），否则运行期改动会被陈旧源覆盖。本次用「运行态变更即回写源」模式兜底。
